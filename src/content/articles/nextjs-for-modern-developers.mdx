Most Next.js content stops at "here is how to make a page." This article starts where tutorials end: the architectural decisions that decide whether your app stays fast, cheap, and maintainable at month six.

## Server Components changed the default

The single most important mental model shift: in the App Router, components are **server-side by default**. You opt into interactivity with `"use client"` instead of opting out with `getServerSideProps`.

That inversion rewards a simple discipline — push client boundaries as deep into the tree as possible:

```tsx
// Page: server component — fetches data, renders static shell
export default async function DashboardPage() {
  const stats = await getStats();
  return (
    <Layout>
      <StatsGrid stats={stats} />          {/* server-rendered */}
      <LiveTicker />                        {/* the only client island */}
    </Layout>
  );
}
```

Everything that does not need event handlers, effects, or browser APIs should stay on the server. Your JavaScript payload is a budget; client components are how you spend it.

## Caching is explicit now

The App Router made caching a set of deliberate choices rather than hidden defaults:

| Layer | Mechanism | Think of it as |
| --- | --- | --- |
| Request memoization | Deduped fetches per render | Free, automatic |
| Data cache | Persisted fetch results | Your database's bodyguard |
| Full route cache | Rendered route output | CDN-grade page cache |
| Router cache | Client-side navigation state | The reason back feels instant |

<Callout variant="info" title="Rule of thumb">
Static by default, dynamic by declaration. Reach for dynamic rendering only when the request itself changes the output — auth headers, cookies, search params.
</Callout>

## Streaming is a UX feature, not a performance trick

Suspense boundaries let you send meaningful pixels immediately while slow data resolves. The pattern that consistently works well:

```tsx
export default async function ProductPage({ params }) {
  const { slug } = await params;
  const product = await getProduct(slug);          // critical: await directly
  return (
    <>
      <ProductHeader product={product} />
      <Suspense fallback={<ReviewsSkeleton />}>
        <Reviews productId={product.id} />          // slow: streamed in later
      </Suspense>
    </>
  );
}
```

Users see the header instantly; reviews fill in without blocking interaction. Perceived performance improves even when total load time barely moves — and perceived performance is what users feel.

## The patterns worth adopting early

### Colocation beats abstraction

Keep data fetching in the segment that needs it. Route-level files (`page`, `loading`, `error`) express intent that middleware-and-context gymnastics never did. Resist building a global data layer "for consistency" — the router already is one.

### Server Actions collapse the API layer

For mutations that originate in your own UI, server actions remove an entire class of boilerplate: no endpoint, no client fetch wrapper, no manual cache invalidation dance.

```typescript
"use server";

export async function createProject(formData: FormData) {
  const name = String(formData.get("name") ?? "").trim();
  if (!name) return { ok: false, error: "Name is required" };
  await db.project.create({ data: { name } });
  revalidatePath("/projects");
  return { ok: true };
}
```

Still expose REST or GraphQL endpoints when third parties consume your API — actions are for first-party forms and mutations.

### Images and fonts: solved problems

Use `next/image` everywhere and `next/font` for typography. They handle formats, sizing, preloading, and layout stability automatically. Manually optimizing either in 2026 is volunteering for work the framework already did.

## Where teams still get burned

- **Giant client bundles from one eager import.** Audit with the bundle analyzer; dynamic-import heavy editors, charts, and maps.
- **Waterfalls disguised as composition.** Sequential awaits in nested layouts chain latencies. Parallelize independent fetches.
- **Over-caching mutable data.** A dashboard showing yesterday's numbers is worse than a slightly slower correct one. Tag and revalidate deliberately.

## The takeaway

Next.js stopped being "React with routing" and became an opinionated rendering architecture. The winners treat it that way: server-first, client islands on purpose, caching as explicit policy, streaming as UX. None of this requires exotic skill — just refusing defaults you have not thought about.

That refusal, applied consistently, is most of what "modern developer" means.
