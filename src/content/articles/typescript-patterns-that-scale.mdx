In small projects, types are documentation. In large ones, they are architecture: the load-bearing structure that decides whether a refactor is a confident afternoon or a week of fear. These are the patterns with the best ratio of payoff to learning curve.

## Model states with discriminated unions

Most runtime bugs hide inside "impossible states" that the type system happily allowed. Discriminated unions make them unrepresentable:

```typescript
// Before: three booleans = eight combinations, five of them nonsense
interface RequestState {
  loading: boolean;
  error: string | null;
  data: User[] | null;
}

// After: exactly four legal states, compiler-enforced
type RequestState =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "error"; message: string }
  | { status: "success"; data: User[] };

function render(state: RequestState) {
  switch (state.status) {
    case "idle":
      return null;
    case "loading":
      return <Spinner />;
    case "error":
      return <ErrorMessage message={state.message} />; // no null-check dance
    case "success":
      return <List users={state.data} />;              // data guaranteed here
  }
}
```

The switch exhaustiveness is the payoff: add a fifth state and every handler that forgot it fails compilation, not production.

## Branded types stop ID mix-ups

`userId` and `orderId` are both strings until they are swapped in a call — at 2am, in prod. Branding makes them different species:

```typescript
type UserId = string & { readonly __brand: "UserId" };
type OrderId = string & { readonly __brand: "OrderId" };

function getUser(id: UserId) { /* ... */ }

getUser(orderId);
// ✅ compile error: Argument of type 'OrderId' is not assignable to 'UserId'
```

Construct them at trust boundaries (API responses, DB rows) once, and the whole interior of the app inherits the safety for free.

## `satisfies`: validation without widening

The pattern for config objects and route maps — check the shape, keep the literal precision:

```typescript
const routes = {
  home: "/",
  articles: "/articles",
  article: (slug: string) => `/articles/${slug}`,
} satisfies Record<string, string | ((...args: string[]) => string)>;

routes.article("types-as-architecture");  // typed precisely
routes.home.toUpperCase();                 // still knows it's a string literal
```

`satisfies` validates against the contract while preserving inference — unlike annotating, which widens and forgets.

## Parse, don't validate

Types describe what you believe. Boundaries decide what is true. Convert external input into typed values exactly once, at the edge:

```typescript
import { z } from "zod";

const ApiArticle = z.object({
  id: z.string(),
  title: z.string(),
  publishedAt: z.coerce.date(),
});

export type ApiArticle = z.infer<typeof ApiArticle>;   // one source of truth

export async function fetchArticle(id: string): Promise<ApiArticle> {
  const res = await fetch(`/api/articles/${id}`);
  if (!res.ok) throw new Error(`Article ${id}: HTTP ${res.status}`);
  return ApiArticle.parse(await res.json());           // lies die here
}
```

After that single parse point, every function downstream receives *proven* types — no defensive checks scattered through the codebase like security guards at every door instead of the entrance.

## Discipline rules that compound

1. **Enable `strict` and never fight it locally.** Every suppression is a future incident report.
2. **Prefer inference for internals, annotations for boundaries.** Public functions declare; private helpers infer.
3. **No non-null `!` assertions outside tests.** If you must convince the compiler, convince it — write the check.
4. **`unknown` at boundaries, narrow deliberately.** `any` is a lie you tell the compiler; `unknown` is honesty it can help you with.
5. **Delete dead types with the same energy as dead code.** Stale types are actively misleading documentation.

None of these patterns is clever. That is the point — the best types are the obvious constraints you were already enforcing in your head, written down somewhere that refuses to let you forget them at scale.
