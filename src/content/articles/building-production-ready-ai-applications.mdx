The gap between an AI demo and a production system is not model quality. It is everything around the model: timeouts, budgets, evals, fallbacks, and a very healthy paranoia about inputs. This field guide covers the practices we now consider non-negotiable.

## Design for degradation, not availability

Traditional services aim for uptime. LLM features need something subtler: **graceful intelligence curves**. When the primary model times out, what happens?

```text
Request flow:
  1. Primary model (best quality)      — timeout: 8s
  2. Fallback model (faster, cheaper)  — timeout: 4s
  3. Cached/heuristic answer           — instant, labeled as such
  4. Honest failure state              — never a hang
```

Each tier should be *visibly* different to users when it matters ("summary generated with reduced context"). Silent quality collapse erodes trust faster than honest downtime.

## Budget like money, because it is

Every request spends tokens; every token costs cents at scale. Three guardrails that prevent 2am incidents:

1. **Per-request ceilings** — max input tokens, max output tokens, enforced in code, not prompts.
2. **Per-user rate limits** — both requests/minute and daily token spend.
3. **Circuit breakers** — when provider error rates spike, shed load to fallbacks instead of retrying into the storm.

```typescript
const result = await withCircuitBreaker("llm-primary", {
  threshold: 0.2,          // trip if error rate exceeds 20%
  intervalMs: 60_000,
  fallback: () => summarizeWithSmallModel(input),
});
```

## Evals are your test suite

You would not ship a refactor without tests. Do not ship a prompt change without evals either.

- **Golden set:** 50–200 real inputs with expected outputs or rubric scores.
- **Regression gate:** CI runs the suite on every prompt/model change; failures block merge.
- **Online measurement:** sample 1 percent of production traffic for human or LLM-judge review.

<Callout variant="warning" title="The silent regression">
Provider silently updates their hosted model and your extraction accuracy drops 8 percent overnight. Teams without pinned versions and eval suites find out from angry users. Be the other team.
</Callout>

## Security: assume the text is hostile

Any string that reaches the model can carry instructions — support tickets, web pages, PDFs, user bios. Defenses in order of importance:

| Layer | Practice |
| --- | --- |
| Privileges | Least-privilege tools; no shared credentials across agents |
| Boundaries | Treat model output like user input — escape before SQL/HTML/shell |
| Context | Separate system instructions from data; prefer structured fields over concatenated strings |
| Audit | Log every tool call with arguments and results |

Prompt injection has no complete fix yet. The goal is making successful injection *boring*: the worst outcome is a wrong answer, not a deleted database.

## Observability for non-deterministic systems

Logs tell you what happened; traces tell you why. For each request capture:

- Full prompt assembly (system, retrieved chunks, user input)
- Raw response plus parsed/validated result
- Latency per stage, token counts, cost
- Trace ID propagated through every downstream call

When quality drops, you diff traces between good and bad days. That diff — not intuition — drives fixes.

## The checklist

Before calling any AI feature production-ready:

- [ ] Timeouts and fallback chain defined and tested
- [ ] Token and cost ceilings enforced server-side
- [ ] Eval suite runs in CI on prompt/model changes
- [ ] Model outputs treated as untrusted input everywhere
- [ ] Traces capture full context for debugging
- [ ] A human approval path exists for consequential actions

None of this is glamorous. All of it is why some teams sleep through launch weeks and others live in incident channels. The model is the easy part — build like you know that.
