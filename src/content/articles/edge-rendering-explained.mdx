"Deploy to the edge" went from conference keynote to default checkbox in three years. But edge is not one technology — it is a spectrum of runtimes with different guarantees. Choosing well requires knowing what the edge actually is and, more importantly, what it is not.

## What "the edge" concretely means

Traditional cloud: a few giant regions. Your users in Lagos reach Frankfurt; physics adds ~90ms before your code even wakes up.

Edge platforms flip the model: hundreds of small points of presence, each able to run your code within a few milliseconds of most humans. The runtime is not Node.js — it is a JavaScript isolate (V8-based, like Cloudflare Workers or Vercel Edge) or increasingly a trimmed WASM sandbox. Cold starts measured in microseconds instead of hundreds of milliseconds.

## What works brilliantly at the edge

- **Middleware: auth checks, redirects, A-B assignment, geo-routing.** The killer app. Decisions made in 2ms instead of 200ms apply to *every* request.
- **Personalization at the CDN layer** — swapping fragments for logged-in states without full origin trips.
- **Static and cached delivery** — already edge-shaped; the edge runtime just adds logic to it.
- **API gateways and aggregation** — fan out to origin services, stitch responses, enforce rate limits close to the client.

```typescript
// The canonical edge workload: cheap, stateless, latency-critical
export const config = { matcher: "/account/:path*" };

export async function middleware(request: Request) {
  const session = await getSession(request);       // signed cookie verify
  if (!session) {
    return redirect(`/login?next=${encodeURIComponent(new URL(request.url).pathname)}`);
  }
  return withExperimentBuckets(request, session);   // assign A/B bucket header
}
```

## What does not belong there (yet)

Honest constraints of current isolates:

| Constraint | Reality |
| --- | --- |
| No filesystem / limited native modules | Image processing via sharp? Not happening |
| CPU-time caps | Heavy transforms get killed mid-request |
| Connection pooling to databases | Traditional drivers assume long-lived TCP; use HTTP-based drivers or poolers |
| Cold caches | Every PoP warms its own cache; first hits pay origin latency |

Databases deserve emphasis: the pattern that works is either HTTP-native databases (Planeteer-style APIs over fetch) or regional connection poolers (Prisma Accelerate, PgBouncer-as-a-service). Raw TCP drivers will burn your CPU-time cap mysteriously.

## The hybrid architecture that actually ships

Nobody moves whole apps to the edge. Winners slice:

```text
┌─────────────── EDGE (every PoP) ───────────────┐
│ middleware: auth/redirects/experiments          │
│ cached pages & assets                           │
│ rate limiting                                   │
└──────────────────────┬──────────────────────────┘
                       │ cache miss / dynamic
┌──────────────────────▼──────────────────────────┐
│ REGIONAL (us-east / eu-west / ...)               │
│ SSR rendering, databases, queues, heavy compute │
└──────────────────────────────────────────────────┘
```

Next.js expresses this split natively: `middleware.ts` runs at the edge, page components render wherever their data lives. You opt routes into edge runtime only when they are stateless and latency-critical.

## A decision rubric

For each route/workload ask:

1. **Is it stateless and fast?** → Edge candidate.
2. **Does it touch a database more than once?** → Regional, probably.
3. **Does the response benefit from caching?** → Edge, aggressively.
4. **Does it need Node APIs, big memory, or long CPU?** → Regional, no contest.

<Callout variant="info" title="Measure, then believe">
Latency wins are real but workload-dependent. Before migrating, measure p95 TTFB per region from real user monitoring — the edge helps Lagos far more than it helps a Frankfurt-only user base already next to your origin.
</Callout>

The mature position in 2026: edge is not the future of all computing; it is the new top layer of it. Put decisions and cacheable bytes there, keep systems of record regional, and let physics work for you instead of ignoring it.
